## 🛡️ 保护机制说明

### 1. 前端访问控制
- **位置**: `quotation_new.html` 中的 `validatePrintingStandardsAccess` 函数
- **功能**: 密钥验证、访问日志、警告提示
- **触发**: 任何对印刷标准的访问或修改操作

### 2. 代码标记保护
- **标记区域**: 核心业务逻辑保护区域
- **警告注释**: 详细的修改警告和要求
- **参数标记**: 每个关键参数都有保护标记

### 3. 完整性检查
- **检查脚本**: `code_protection_check.py`
- **哈希验证**: 基于代码内容的完整性校验
- **基线对比**: 与已知正确版本进行对比

## 🔧 安全修改流程

### 步骤 1: 权限验证
```bash
# 1. 运行保护检查脚本
python code_protection_check.py

# 2. 确认当前状态正常
# 3. 记录当前基线哈希值
```

### 步骤 2: 解锁访问
1. 打开印刷标准管理页面: `http://localhost:5000/printing_standards_admin`
2. 输入管理员密钥
3. 临时解锁系统（如需要）
4. 记录操作日志

### 步骤 3: 代码修改
1. 打开 `quotation_new.html` 文件
2. 找到保护区域（搜索 "核心业务逻辑保护区域"）
3. 在修改前添加注释说明修改原因
4. 仅修改必要的参数，保持代码结构不变
5. 保留所有保护标记和注释

### 步骤 4: 测试验证
```bash
# 1. 运行功能测试
python test_frontend_logic.py

# 2. 验证特定尺寸的计算结果
# 例如: 300x500mm 应该匹配 "4开机器"

# 3. 运行完整性检查
python code_protection_check.py
```

### 步骤 5: 更新基线
```bash
# 如果修改正确，更新基线
# 删除旧的基线文件
del printing_logic_baseline.txt

# 重新生成基线
python code_protection_check.py
```

### 步骤 6: 重新锁定
1. 返回印刷标准管理页面
2. 重新启用锁定保护
3. 更新管理员密钥（建议）
4. 记录修改完成日志

## ⚠️ 常见错误和注意事项

### 🚫 禁止操作
- **删除保护标记**: 绝不删除任何保护注释或标记
- **修改函数结构**: 不要改变函数的基本结构
- **绕过验证**: 不要试图绕过密钥验证机制
- **批量修改**: 避免一次性修改多个参数

### ⚠️ 注意事项
- **尺寸判定逻辑**: 使用 `Math.max` 和 `Math.min` 确保长宽不受顺序影响
- **边界条件**: 注意尺寸范围的边界值处理
- **价格一致性**: 确保与数据库中的价格标准保持一致
- **测试覆盖**: 测试各种尺寸组合，特别是边界值

## 🔍 故障排除

### 问题: 密钥验证失败
**解决方案**:
1. 检查密钥是否正确
2. 确认锁定状态
3. 联系系统管理员重置密钥

### 问题: 完整性检查失败
**解决方案**:
1. 运行 `python code_protection_check.py` 查看详细信息
2. 检查是否有意外的代码修改
3. 恢复到最后一个正确的版本
4. 重新按流程进行修改

### 问题: 计算结果不正确
**解决方案**:
1. 检查尺寸判定逻辑
2. 验证价格参数
3. 运行测试脚本确认
4. 对比数据库标准
