# 判定逻辑修复说明

本次修复目标：检查并统一报价系统里“材料/工艺/印刷/模切/覆膜/光油等所有判定标准”的匹配逻辑，避免价格没有按用户维护的判定标准走。

## 发现的问题

1. 前端报价页 `quotation_new.html` 里存在部分写死的特殊计算逻辑，尤其是印刷组件：
   - 印刷会被 `isPrintingComponent` 和 `getTieredPrintingUnitCost` 走单独分段逻辑；
   - 这会绕开或覆盖后台维护的判定标准。

2. 工艺判定依赖 `/api/pricing_standards/match`，但当前需要明确统一规则：
   - 所有工艺都必须先按判定标准匹配；
   - 不允许某个工艺私自用固定公式覆盖；
   - 印刷、模切、覆膜、光油、烫金、压痕等都要用同一套匹配方式。

3. 尺寸判断必须同时考虑：
   - 长度范围：`min_length <= length <= max_length`
   - 宽度范围：`min_width <= width <= max_width`
   - 同时要支持长宽互换判断：例如输入 400×300，也应该能命中标准 300×400。

4. 如果多条标准都命中，应按优先级和范围精确度排序：
   - `priority` 越大越优先；
   - 尺寸范围越窄越优先；
   - 数量范围越窄越优先；
   - 最近创建或 ID 较大的作为最后兜底。

## 建议的统一判定规则

材料类标准按照材料分类匹配：`standard.type = material`，`standard.material_category_id = 当前材料分类ID`，长宽和数量必须落在范围内。

工艺类标准按照当前选择的工艺名称匹配：印刷、模切、切割、光油、覆膜、烫金、压痕、装订、折页、打孔、损耗都必须走同一套判定。

尺寸必须支持两种方式：

```text
正常方向：length 在长度区间，width 在宽度区间
旋转方向：width 在长度区间，length 在宽度区间
```

价格计算建议统一为：

```text
工艺单价 = 基础价格 / 实际数量 + 面积 × 平方价格
实际数量 = 项目套数 × 行数量 + 损耗数量
面积 = (长 + 材料下单增加长) × (宽 + 材料下单增加宽) / 1000000
```

印刷不再单独写死“3000以内/3000以上”的前端逻辑。要分段时，应在判定标准里维护多条数量范围。

## 需要修改的文件

### 1. `电脑报价系统/app.py`

重点修改 `/api/pricing_standards/match`：

```text
1. 后端统一完成材料标准和工艺标准匹配。
2. 支持长宽互换。
3. 支持 priority 排序。
4. 返回 matched_standard、matched_material_standard、debug 信息。
5. 不要让前端自行判断不同工艺应跳哪条标准。
```

### 2. `电脑报价系统/templates/quotation_new.html`

重点修改：

```text
calculatePrice(row)
isPrintingComponent(component)
getTieredPrintingUnitCost(...)
```

要求：

```text
1. 移除或停止使用印刷单独分段逻辑。
2. 所有工艺都使用 /api/pricing_standards/match 返回的标准。
3. 计算标准浮窗里显示：命中的标准名称、类型、长宽范围、数量范围、基础价、平方价、损耗。
4. 如果没有命中，明确显示“未命中判定标准”，不要静默用默认工艺价。
```

## 手工测试清单

1. 新建一条印刷标准：长 0-500，宽 0-500，数量 1-3000。
2. 报价页输入 400×300，选择印刷，应命中该标准。
3. 报价页输入 300×400，也应命中同一条标准。
4. 新建一条模切标准，用同样尺寸测试，也应命中。
5. 把数量改到 3001，如果有 3001 以上标准，应自动切换。
6. 没有标准时，价格明细必须显示“未命中判定标准”。
